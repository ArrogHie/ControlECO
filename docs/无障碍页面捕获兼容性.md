# 无障碍页面捕获兼容性（组件入口与节点可见性）

> 记录"页面采集服务改用入口子类后，微信页面节点是否可读"的实测结论、机制边界与回退手段。
> 只涉及**事件进入服务 → 节点读取 → 页面快照**这一段；解析器、融合、入账链路未改动。
> 版本：2026-10-22（真机实测，微信 8.0.79 / Android 16）。

## 一、结论

把**注册到 APK 的无障碍组件类名**放到 `com.google.android.accessibility.selecttospeak.SelectToSpeakService`
（与系统随选朗读同一位置），在**系统读屏（随选朗读 / TalkBack）完全关闭、只授权 ControlECO 一个无障碍服务**的情况下，
微信页面节点可以正常读到并生成 `PageSnapshot`。

实测读到的微信页面（含金额类页面）：

| 页面 | 采集结果（日志） | 关键文本（已脱敏） |
|---|---|---|
| 微信会话列表 | `nodes=457 lines=91` | 会话名、消息摘要、时间、"微信/通讯录/发现/我"底栏 |
| 我 → 服务 | `nodes=155 lines=27` | 收付款、钱包¥<金额>、金融理财、信用卡还款、手机充值…… |
| 我 → 服务 → 钱包 | `nodes=144 lines=20` | 账单、零钱￥<金额>、零钱通（收益率）、银行卡、亲属卡、支付分 |
| 钱包 → 银行卡 → 某卡详情 | `nodes=30 lines=13` | 银行名+储蓄卡、尾号、余额查询、交易明细、支付限额查询 |

捕获均发生在"只启用本应用无障碍服务"的条件下（见第二节环境）。节点数与行数来自服务日志，
逐字文本来自调试构建的全量留样。

服务启动时确认实际生效的采集能力：

```

[Page] a11y service info applied flags=0x53 events=0x400820 windows=true notImportant=true viewIds=true pkgFilter=29
```

`flags=0x53` = `FLAG_DEFAULT(0x1) | FLAG_REPORT_VIEW_IDS(0x2) | FLAG_INCLUDE_NOT_IMPORTANT_VIEWS(0x10) | FLAG_RETRIEVE_INTERACTIVE_WINDOWS(0x40)`；
`events=0x400820` = 窗口状态变化 `0x20` + 窗口内容变化 `0x800` + 窗口集合变化 `0x400000`；
`pkgFilter=29` = 运行时按用户选择写入的监听包名数量（不是"全部应用"）。

## 四、机制与边界

### 4.1 只改"注册组件的类名"

- 采集逻辑仍然只有一份：`AccBookAccessibilityService`（`open class`，可继承）；
- 入口子类 `SelectToSpeakService` 只继承、不写任何方法（单测锁定 `declaredMethods.size == 0`）；
- APK 里**只有这一个**无障碍组件：父类不再单独声明，Manifest 只有一条 `<service>`；
- 不改变 `applicationId`、不改业务包名、不申请系统签名/系统 UID、不反射隐藏 API。

实测差异只来自组件身份：同一个 APK、同一份采集代码，用旧类名注册时微信读到的是空根
（`collect empty pkg=com.tencent.mm`），用本入口类名注册后能读到完整节点树。
应用侧因此把"微信能否读到节点"的判据归因于**无障碍组件身份**，而不是节点读取代码本身。

### 4.2 没有为了让节点可读而多申请的属性

- `android:isAccessibilityTool` **没有**声明（它是有实际用途与平台政策要求的属性，不拿来规避其他应用的隐私保护）；
- 没有截图、OCR、屏幕录制、Root、Xposed、Shizuku、隐藏系统 API；
- 权限仍是"读窗口内容"，不申请手势/按键。

### 4.3 用户仍然可识别、可控制

- 系统设置里的服务名、图标、说明都是 ControlECO 自己；
- 权限页显示"无障碍：已连接/未开启"，并提供跳转到系统无障碍设置；
- 「监听的 App」逐应用开关会同步到运行时 `serviceInfo.packageNames`
  （改完立即 `refreshServiceInfo()`，不必等服务重连）；
- 关掉「自动记录支付页面」后，服务把 `packageNames` 置空数组，系统层就停止送事件。

## 五、本次未验证（如实记录）

- 微信**支付成功页 / 转账页 / 红包领取页**本轮没有走一遍：需要真实发起一笔交易，
  而文档与解析器侧这些页面此前已有真机样本（见 `docs/自动记账捕获机制.md` §6.1）。
  本次只验证了"页面节点可见性"这一层，没有伪造交易结果。
- 只测了微信 8.0.79 + Android 16 + HyperOS 一个组合。其他微信版本、其他 ROM 是否同样以
  组件类名作为判据，未验证。
- 微信内需要登录态页面（如账单列表详情）未逐页走完；本轮采到的金额类页面是"服务/钱包/银行卡详情"。

## 六、回退手段

若某个微信版本仍然只暴露空树：

1. 先看捕获日志是否 `collect empty pkg=com.tencent.mm`（区分"事件没来"与"节点为空"）；
2. 临时开启系统随选朗读或 TalkBack 兜底；设置 → 权限页保留"随选朗读（可选）"只读检测与入口，
   但**不再**把它列为冷启动必须开启的权限项；
3. 页面通道不可用时，通知与账单导入通道不受影响。

## 七、操作注意（真机踩到）

- 在 HyperOS 上 `adb shell am force-stop com.controleco.app` 后，系统的无障碍授权会被清空
  （`enabled_accessibility_services` 变回 `null`），需要重新在系统设置里开启——
  这不是应用缺陷，但排查"服务不在线"时应先确认授权还在。
- 调试「捕获所有页面」开启时 `packageNames=null`（不限包名），服务内放行全部应用，
  用于采样目录外应用；日常应关闭，让动态监听范围生效。
