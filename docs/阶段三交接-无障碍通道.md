## 二、阶段三目标（来自开发方案第三节）

1. **无障碍抓取**：读取微信/支付宝「支付成功页」「账单详情页」，补全商户与支付方式——这是"支出类通知信息稀疏"的解法，也是准确性的主力通道。
2. **悬浮确认卡**：支付完成瞬间在支付页上方弹出预填金额/商户的确认卡（底部卡）：关闭即入账、点「忽略」不入账。
3. **权限引导补全**：无障碍开启引导 + 安卓 13+ 侧载"允许受限制的设置"解锁步骤 + 各品牌支付保护关闭指引。

## 三、建议实施步骤

### 1. 无障碍服务骨架
- 新建 `capture/AccBookAccessibilityService` + `res/xml/accessibility_service_config.xml`：
  - `packageNames` 限定 `com.tencent.mm`、`com.eg.android.AlipayGphone`（后续云闪付）
  - 事件只订阅 `TYPE_WINDOW_STATE_CHANGED` + `TYPE_WINDOW_CONTENT_CHANGED`；`canRetrieveWindowContent`；**不要**申请手势/按键能力（最小化权限，商店与系统审查都看这个）
- Manifest：`BIND_ACCESSIBILITY_SERVICE` 权限 + meta-data 指向配置 xml
- 开关与状态：设置页加"无障碍抓取"开关；服务连接状态接入 `CaptureCenter`（新增状态流，参照 `connected` 的做法）；服务被杀检测复用保活页思路
- 开启检测：`Settings.Secure.ENABLED_ACCESSIBILITY_SERVICES` 包含本服务类名；跳转 `ACTION_ACCESSIBILITY_SETTINGS`

### 2. 页面识别规则（核心工作量）
- 新建 `capture/PageRules.kt`，风格对齐 `NotificationRules`（纯函数、可单测、样本驱动）：
  - 输入：包名 + 当前窗口节点文本集合（展开 text/contentDescription，**只收文本，不要存 viewId 依赖**）
  - 页面判定按**文本特征**：支付成功页（含"支付成功/已支付/付款成功"）→ 提取金额、收款方（"收款方："、"对方"行）；账单详情页（含"账单详情"）→ 金额/商户/支付方式/交易时间
  - **防抖**：内容变化事件高频，需 300~500ms 节流 + 页面文本指纹去重（同页只解析一次）
  - debug 全量打印页面文本快照到 Logcat（tag=AccBook，同通知的做法）——真实页面样本靠它收集，规则失效时靠它定位
- 接入采集链路：`CaptureCenter` 新增 `onPageCaptured(...)` 入口：
  - 原始快照落库（captured 表复用：建议加 source 列或以 `a11y:` 前缀包名区分，二选一需 **Room v5 迁移**，流程照旧）
  - 待确认入队，dedupKey **必须与通知通道同构**（`包名|TYPE|金额|分钟`）——同一笔交易"通知+页面"双捕获时天然去重，只入一次
  - note 存页面提取的关键行（⚠️ 不要把余额/卡号整页塞进去，只取需要字段）
- 悬浮窗确认入账也走同一 dedupKey（externalId=`NTF:`+dedupKey），保证三通道（通知/页面/悬浮确认）不重复

### 3. 悬浮确认窗
- Manifest 加 `SYSTEM_ALERT_WINDOW`；设置页引导授权（`ACTION_MANAGE_OVERLAY_PERMISSION` 跳转）
- `TYPE_APPLICATION_OVERLAY` + 精简 UI：金额/商户/默认分类/默认账户 + 确认/忽略；确认直接入账（不走待确认）
- 已知拦截：华为/荣耀"支付保护中心"、小米"支付保险箱"会盖住支付页拦悬浮窗——`KeepAliveScreen` 已有华为提示，补小米/OPPO 文案

### 4. 权限引导补全（改 KeepAliveScreen 即可，框架已具备）
- 加"无障碍"状态卡：可检测 + 跳转系统无障碍设置
- 安卓 13+ 侧载：开启无障碍前需"应用信息→右上角→允许受限制的设置"——**写成分品牌通用第一步**
- 支付保护关闭指引（见上）

## 四、验收标准

1. 真机微信扫码付款 → 悬浮窗弹出、预填金额/收款方，确认即入账；关闭悬浮窗授权时降级为"页面捕获进待确认队列"
2. 支付宝账单详情页捕获出商户/支付方式（对照捕获日志文本快照核对）
3. 同一笔交易 通知+页面 双通道只入账一次
4. 全量既有测试通过；PageRules 有真实页面文本快照的用例（收集方式同通知：debug 日志）
5. 无障碍被系统/用户关闭后，保活页状态卡能显示异常并引导

## 五、风险与约束（读一遍再动手）

- **规则失效是常态**：微信/支付宝改版会让文本特征失效——按"文本特征"写规则、debug 页面快照日志定位、样本固化为用例，与通知规则同一套维护流程（维护指南第一节）
- 安卓 13+ 侧载的"受限制的设置"：无障碍与通知使用权都要解锁，真机测试第一步
- `accessibilityDataSensitive`（安卓 14+）：平台预留的对抗手段，微信/支付宝目前未启用，监控即可，不要提前设计绕过
- 事件风暴：无障碍事件量极大，节流与包名过滤做不好会卡顿耗电；`accessibility_service_config` 里的事件类型/包名过滤是第一道闸
- 隐私：页面文本可能含卡号/余额，入队 note 只存提取字段；捕获日志本身 7 天/2000 条自动清理
