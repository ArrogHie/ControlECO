# 金额与预算计算

核对基线见[文档索引](README.md)。以下 `/` 在整数公式中表示整数除法；非负金额向下截断。金额单位均为分，展示时才转元。

## 1. 金额表示与舍入

- `amountCents: Long` 保存账面金额，收支方向由 `TxType` 决定。正常手工输入和捕获使用正金额，收入预算标记强制清空。
- `Money.parseCents` 以 `BigDecimal` 转分，最多两位小数；不把第三位小数四舍五入。支持负号、人民币符号及合法千分位，普通解析不接受前导 `+`（页面带符号金额由专用函数先拆符号）。导入解析目前未另行拦截零或负金额，不应将“所有入库金额都有统一正数校验”当作数据库约束。
- 更换货币只更换显示符号，不做汇率换算，也不改变两位小数的存储单位。
- 显示紧凑金额时，整数部分超过四位才逐级换成 K／M／B，各档保留最多两位小数；这不改变入库和计算金额。

## 2. 三种金额口径

设一笔支出的账面金额为 `m`，AA 人数为 `n`：

```text
A(m,n) = n >= 2 时 (m + n/2)/n，否则 m
实际支出贡献 = 已退款支出 ? 0 : A(m,n)
预算支出贡献 = 已退款支出或不计入预算 ? 0 : A(m,n)
```

AA 输入为 2–99 人，默认 2 人；未开启存 0。**逐笔折算并四舍五入到分，再求和**，并非先加总再均摊。AA 不生成收款、报销或其他人的账单，不改原账面金额。例如 100 元三人 AA，个人支出按 33.33 元统计。

| 读数 | 计算口径 |
| --- | --- |
| 账单金额、账单封面收支、统计封面收支、支出柱状图 | 原账面金额，含已退款原支出，不折算 AA，不受“不计入预算”影响 |
| 本期结余 | 本期账面收入 − 本期账面支出；不是总账户余额 |
| 统计“实际支出”、分类占比、预算对比中的实际金额 | 未标已退款的支出，逐笔 AA 折算；“不计入预算”不使其归零 |
| 首页“本月已花”、今日预算支出、分类剩余预算、个人页预算读数 | 未标已退款、未勾“不计入预算”的支出，逐笔 AA 折算 |
| 单账户余额 | 初始余额 + 该账户全部收入 − 全部支出；不限当前周期，始终使用账面金额 |
| 首页总存款 | 所有账户余额之和；不是从银行读取的余额 |

两种预算标记同时开启时：实际支出按 AA 折算，预算贡献为 0。退款收入仍计入账面收入，**不会再从实际支出或预算支出中相减**。

例：同一期有普通支出 100 元、90 元三人 AA、50 元“不计入预算”、已标全额退款支出 80 元，以及退款收入 80 元：

| 结果 | 金额 |
| --- | ---: |
| 账面支出／账面收入 | 320.00／80.00 |
| 本期结余 | -240.00 |
| 实际支出 | 180.00（100 + 30 + 50） |
| 计入预算的支出 | 130.00（100 + 30） |
| 所有账户合计相对初始余额的变化 | -240.00 |

## 3. 退款影响

`REFUNDED_EXPENSE` 是支出上的整笔标记；`REFUND_INCOME` 是独立退款收入。两者之间没有关联 ID。设置支出已退款不会改账户余额或账面支出，只改变实际支出、预算统计。

- 新捕获退款先进入待处理，不参与余额、收入和支出汇总；用户选择原支出后，才生成全额退款收入并标记原支出已退款。
- 已捕获金额时只能选择同额支出；未捕获金额时采用选中支出的全额。当前退款操作不提供部分金额输入。
- 旧版本已入账的 `refundPending=true` 退款继续参与收入；处理时只改标记，不重复产生收入。
- 支出编辑页“退款该账单”同时生成全额退款收入；“撤销退款”恢复原支出的实际支出／预算贡献，并删除原支出之后第一笔同金额的“退款”收入。按业务时间排序，同时间以 ID 排序，不按账户／商户匹配，不增加数据库关系。
- **导入的部分退款**：微信状态中提取到的退款额小于原金额时保留普通支出；支付宝部分退款原支出仍为“交易成功”时也保留。退款收入另计收入，因此实际支出、预算不是“原支出减部分退款”。具体导入判定见[业务与数据模型](业务与数据模型.md)。

跨周期退款不会把退款额挪回原月份：收入归其自身时间；原支出被标已退款后，原支出所在历史周期的实际支出和预算统计随之变化。删除任一记录不会自动撤销另一记录的标记。

## 4. 会计周期

- 设备本地时区，查询区间统一为 `[开始日零点, 结束日零点)`。
- 每月首日可选 1–30 日或“月末”（内部存 0）。29／30 日遇短月取该月最后一天；月末始终取当月最后一天。
- 月份标签指开始所在的自然月。例如首日为 5，“2026 年 10 月”是 `[10-05,11-05)`，界面最后一天显示 11 月 4 日。
- 首日为 30 时，非闰年 2 月周期为 `[02-28,03-30)`；首日为月末时为 `[02-28,03-31)`。
- 年视角为当年 1 月有效首日到次年 1 月有效首日，含 12 个会计月。年柱状图也按会计月分桶。
- 首页固定当前会计月；账单与统计共用所选月份和月／年模式。筛选、搜索都在该选定周期内。

`D = 本期天数`；`L = max(今天到结束日的日数,1)`（含今天）；已过天数为 `clamp(开始日到今天的日数+1,1,D)`。刷新“今天”由页面恢复前台等调用 `refreshToday`，不是后台每天结算一份预算。

## 5. 总预算与每日读数

设生效月预算 `B`、本期预算支出 `S`、今日预算支出 `T`：

```text
月预算模式：B = 设置的月金额
日预算模式：B = 设置的日金额 × 当前会计月天数 D
剩余预算 R = B − S
消耗比例 = S / B；剩余比例 = R / B（比例计算使用浮点数）
月模式建议日额 = R > 0 ? R/L : 0
日模式建议日额 = 设置的日金额（其 > 0 时）
本日剩余 = 建议日额 − T
```

`B<=0` 时 `Budget.compute` 返回空，界面显示未设预算。剩余预算和本日剩余均可为负；收入不增加当天预算。

月模式的 `R` **已经扣过今天的支出**，计算本日剩余时仍再减 `T`，这是当前公式，不能改写成“期初日均预算减今日支出”。例如 `B=3000 元、S=600 元、L=20、T=50 元`，建议日额为 120 元，本日剩余为 70 元。

个人页预算卡的“日均”另用 `Budget.dailyEquivalent`：月模式为 `(B+D/2)/D`，四舍五入到分；日模式直接显示日金额，**不是剩余预算的建议日额**。

切换预算模式仅在目标金额未设置时预填：月转日为 `(月金额+D−1)/D`（向上取整到分），日转月为 `日金额×D`。已有目标金额不被覆盖。

预算设置是当前配置，没有按历史月份保存快照；修改预算、分类比例或首日会改变相关展示。

## 6. 分类预算与占比

分类预算有金额、比例两个全局模式。比例以万分比 `p` 存储，`100=1%`，单项范围 `0..9999`（最高 99.99%）：

```text
比例转分 = (B×p + 5000)/10000
金额转比例 = clamp((分类金额×10000 + B/2)/B, 0, 9999)
分类剩余 = 分类预算 − 该分类预算支出
```

切换金额／比例模式会用当前生效月预算转换，存在分与万分比舍入；没有约束所有分类预算之和必须等于月预算。

首页仅单列正预算的支出分类。其余分类汇总为“未设预算分类”：预算为 `max(B−已分配预算,0)`，支出为 `S−已分配分类的预算支出`；预算或支出为正即显示。它与真实的“其他”分类不同。

首页头部分类剩余仍为 `B−S`。分类预算总和不超过 `B` 时，等于各条剩余之和；超出 `B` 时，**各条剩余之和比头部多出超配预算**，不能据分类条反推总预算。

统计页：

- 预算对比清单的实际占比 = 分类实际支出 ÷ 全部实际支出；预算占比 = 分类预算 ÷ 所列分类预算总和，分母不是全局月预算。
- 分类双环的外环按分类预算总和分配角度，内环按实际支出总和分配角度，各自填满有数据的一圈。**圆环左侧金额下面的百分比**另用“当前显示的实际金额 ÷ 分类预算总和”：未选中是全部实际支出占预算总和，选中是该分类实际支出占预算总和，可超过 100%，与清单实际占比不同。右侧为当前分类预算占总分类预算；未选中且总预算为正时显示 100%。
- 预算对比的“实际”包含“不计入预算”的支出（仍折算 AA），不能拿它代替首页分类剩余计算。
- 年视角分类预算 = **当前有效分类月预算 ×12**，不逐月重算日数、不读取历史配置。
- 百分比各自四舍五入为整数，显示之和可能不是 100%；零分母返回 0。
- 支出趋势柱按账面支出求和，含已退款原支出；每笔计数为 1，AA 不分拆笔数。当前页面不展示旧辅助组件中的“日均结余”。

## 7. 预算颜色与图形

总预算和有预算分类使用相同阈值，设剩余比例为 `r`：

```text
绿线 G = max(L−1,0)/D
红线 H = (L/2.0)/D
r > G：绿（充裕）
否则 r >= H：黄（留意）
否则：红（偏紧）
r < 0 的文字标签：已超支
```

判断按上述顺序，绿线用严格大于。最后一天 `G=0`，正剩余比例先命中绿色，不可交换判断顺序。

动画警示强度为 `clamp((H−r)/(H+0.3),0,1)`：红线处为 0，剩余比例达到 -30% 时封顶。

`Budget.State` 是另一个状态：`R<=0` 为 CRITICAL，否则消耗比例 ≥75% 为 WARNING，其余 NORMAL；它不是颜色阈值。圆环绘制进度会限制在 0–1，金额和剩余百分比仍可显示负值。
