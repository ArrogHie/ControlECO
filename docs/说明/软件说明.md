# 软件说明

易控钱包支持手工记账、微信／支付宝账单导入，以及通知、支付页面、银行短信捕获。本文以当前仓库为准，详见[文档索引](../README.md)。

## 预算与账单读数

- **账单结余**＝所选周期全部账面收入－全部账面支出。退款、AA 和“不计入预算”不改账面金额。
- **实际支出**＝未标“已退款”的支出；AA 按金额除以人数、逐笔四舍五入到分，“不计入预算”仍参与实际支出。
- **首页已花／剩余预算**使用预算口径：在实际支出的基础上，再排除“不计入预算”的账单。
- **总存款**＝所有账户初始余额＋全部账面收入－全部账面支出，不是银行实时余额。
- AA 不自动生成他人还款记录；更换货币只换符号，不换算汇率。

每月首日可选 1–30 日或月末。周期含首日、不含下一期首日，遇短月按该月最后一天作为边界。账单和统计可翻月／年，首页始终显示当前会计月。

月模式建议日额＝正的剩余预算÷剩余天数（含今天）；本日剩余再减今日预算支出。日模式为日预算减今日预算支出。个人页日均使用月预算÷本期天数，与建议日额不同。舍入、颜色阈值和示例见[金额与预算计算](../金额与预算计算.md)。

## 自动记账设置

在设置→权限开启需要的采集通道，在“监听的 App”选择来源。通知使用权负责读取其他应用通知；本应用通知权限负责发送提醒，两者不同。银行短信仅接收新到短信，不读取历史短信，默认关闭。

普通有效候选满足金额、分类、账户要求时：

| 设置 | 行为 |
| --- | --- |
| “入账提醒”“悬浮窗入账”“自动入账”任一开启 | 普通交易先入账，再按开关弹卡或发通知 |
| 三项全部关闭 | 留在待确认列表，由用户入账 |
| 仅开启“自动入账”，其余关闭 | 直接入账，不弹普通卡或入账通知 |

“悬浮窗入账”与“自动入账”互斥；入账提醒独立。**只关闭自动入账不等于逐条确认模式。** 没有识别出候选时，不会凭空创建账单。

普通悬浮卡约延迟 3 秒，60 秒无操作关闭；已入账记录保留，有效编辑同步，“忽略／撤销”删除该笔。卡片无法展示时已入账记录仍保留；通知兜底需入账提醒开启及系统通知授权。

金额缺失先待补录，不能按 0 元入账。微信红包领取页为特殊询问：金额仅预填，必须点“记一笔”或在待确认页逐条确认；关闭／超时保留待确认，“全部确认”不处理红包。

## 退款与导入

自动捕获的退款先进入“待处理”。有金额时，从同金额未退款支出中按日期区间查找；无金额时，可按商户、金额区间、日期区间查找全部未退款支出。选中后新增退款收入，原支出退出实际支出和预算。

在支出编辑页选择“退款该账单”可全额退款；“撤销退款”恢复原支出，并删除该支出之后第一笔同金额的“退款”收入。“记一笔”不能直接新增退款收入。旧版待处理退款与导入账单保持兼容。

导入账单全归本次选定的账户。有单号的重复导入跳过已有行，不更新原记录；自动捕获与导入之间不自动对账去重。详见[业务与数据模型](../业务与数据模型.md)。

## 漏记与重记排查

1. 查看权限、采集通道、监听来源及“保活与自启动”。目录可监听不代表所有页面均能识别。
2. 捕获日志确认事件有没有到达、原文是否含金额与成功状态。“记录记账来源”需提前开启，不补记过去的捕获。
3. 同笔可能来自支付应用、商家和银行。常规匹配窗口为首次捕获后 180 秒，仍有金额、方向、身份及来源限制；页面时间／订单号另有去重路径。
4. 窗口外、进程重启、页面变化或证据不足时仍可能漏记／重记，可手动修改、删除或导入补录。反馈提供脱敏来源、时间、金额、机型与捕获／溯源记录。

页面采集读取可访问节点，不做截图 OCR、不读支付应用私有数据库。受保护页面可能不可读，部分银行应用可能限制无障碍启用时的使用；可临时关闭本应用无障碍后重试。[兼容性记录](../无障碍页面捕获兼容性.md) 仅是特定设备历史实测，不代表全机型保证。
