# 10 · 导入账单

从个人页「导入账单」、设置 → 账单导入、分享文件（`ROUTE_IMPORT_FILE_PREFIX`）进入。四阶段同页：选择文件 → 解析中 → 预览 → 完成。

源码：`app/src/main/java/com/controleco/app/ui/imports/ImportScreen.kt`（约 709 行）

---

## 1. 路由与入口

- 路由：`import`。
- 进入：
  - 个人页底排「导入账单」→ `settings/import` → 选择账单文件 → `import`
  - 分享文件：`vm.parseBillFile(uri)` 后直接 `navigate("import")`
- 离开：
  - 返回
  - 完成后「返回」
  - 完成后「继续导入」→ 清空状态回到阶段 0（不离开页面）
- 页面 `onDispose` 会 `vm.clearImportState()`，离开即丢弃未提交的解析结果。

## 5. 状态与数据流

### VM

- `parsedBill: ParsedBill?`
- `importError: String?`
- `importDone: ImportCommitResult?`
- `accounts`

### 本地

- `accountId`：默认第一个账户；`LaunchedEffect(accounts)` 补默认。
- `parsing`：文件已选、结果未到的中间态。
- `LaunchedEffect(bill, error)`：任一到达即 `parsing = false`。

### 文件选择

`rememberLauncherForActivityResult(OpenDocument())`，`picker.launch(arrayOf("*/*"))`。
选择后：`parsing = true` → `vm.parseBillFile(uri.toString())`。

> 分享文件进入时，`AppNav` 已经调用过 `parseBillFile`，本页只需展示结果。

### 阶段优先级

1. `done != null` → 完成
2. `bill != null` → 预览
3. `parsing && error == null` → 解析中
4. 否则 → 选择文件（含错误）

### 预览数据

- `bill.source.displayName`：识别来源（微信/支付宝）。
- 条数：总 / 支出 / 收入；跳过“不计收支”“未完成”的条数。
- 退款：`refundCount`；导入**不做任何配对**——只知道哪些支出被退款了，不需要“配对/匹配”这个操作。
  微信「已全额退款」的原支出、支付宝「交易关闭」的原支出直接标 `REFUNDED_EXPENSE`（显示「已退」，不再计入支出）；
  微信部分退款（「已退款(¥X)」）的原支出**不标**（照常全额计入支出）；退款行记为收入 + `REFUND_INCOME`、`refundPending = false`。
- 预览只取前 **8** 条。
- 账户为空时提示“暂无账户，请先在账户管理中添加”，禁用确认。
- 确认导入：`onCommit = { accountId?.let { vm.commitImport(bill, it) } }`。

### 完成

`ImportCommitResult`：`inserted`、`duplicated`；显示记入账户名。
「继续导入」→ `reset()`（清 VM 状态 + `parsing=false`）。
「返回」→ `onBack()`。

## 7. 文案

- 顶栏：`IMPORT` / `导入账单`。
- 阶段条：`01 选择文件`、`02 预览`、`03 导入`、`04 完成`（注意：解析中显示的是 `02` 预览前的进度）。
- 选择区：`从本机选择账单文件`、`微信 xlsx / 支付宝 CSV`、`选择账单文件`。
- 页尾：`文件只在本机解析；导入会跳过已存在的记录（按来源 + 时间 + 金额 + 方向去重）。`
- 教程：`导出方法 / HOW TO`；微信 `我 → 服务 → 钱包 → 账单 → 右上角常见问题 → 下载账单 → 用于个人对账（xlsx 发送到邮箱）。`；支付宝 `我的 → 账单 → 右上角「…」 → 开具交易流水证明 → 用于个人对账（CSV 发送到邮箱）。`
- 解析中：`正在解析账单…`、`读取行、识别来源、生成去重键`。
- 预览：`识别为：{来源} 账单`、`共 N 条（支出 X，收入 Y）；已跳过不计收支 A 条、未完成 B 条。`、`其中退款相关 N 条（已入库：退款收入记入收入，被退款的原支出标记为「已退款」、不再计入支出）`、`记入账户`、`暂无账户，请先在账户管理中添加`、`没有可导入的记录` / `文件里没有可入账的收支记录，换一个文件试试。`、`确认导入 N 条`、`换一个文件`。
- 完成：`导入完成`、`成功导入 N 条，跳过重复 M 条。`、`已记入「账户」。`、`继续导入`、`返回`。
- 错误：`导入失败`、`重试`。

## 9. 坑与验收

**坑**

1. **页面离开即清空导入状态**（`onDispose`），这是有意避免残留；不要为了“回来还能看到”去掉。
2. 阶段优先级不能乱：`done` > `bill` > `parsing` > idle；否则完成页会被预览覆盖。
3. 预览只显示前 8 条，但「确认导入 N 条」的 N 是 `bill.rows.size` 全量；不要改成 8。
4. 无账户时确认按钮必须禁用；去账户管理再回来，`accountId` 需要重新补默认。
5. 退款记录永远入库、永远显示（不再有显示开关）：退款收入永远计入收入，被标「已退款」的原支出不再计入支出；**退款收入固定归「退款」分类**，预览行也按这个口径显示，不要回退成按商户名猜的分类。
6. 分享文件进入时不要重复调用 `parseBillFile`（`AppNav` 已调用）；否则会解析两次。
7. 文件选择用 `OpenDocument` + `*/*`，不是图片选择器；不要换成 `PickVisualMedia`。
8. `ImportStageBar` 只有 4 步，解析中仍显示“02 预览”之前的进度；这是现有设计，不要新增第 5 步。
9. 解析失败时 `parsing=false` 且 `error!=null`，会回到 idle + 错误卡；不要卡在转圈。
10. **导入只做标记、不做配对**：微信「已全额退款」、支付宝「交易关闭」的原支出标 `REFUNDED_EXPENSE`；
    没有标记的普通支出不能当候选，**不要按金额/商户猜哪笔退款对应哪笔支出**。
11. 导入的退款行一律 `refundPending = false`，不进待确认；重复导入的记录由去重键拦掉。

**验收**

- [ ] 四个阶段按优先级正确切换。
- [ ] 解析失败有错误卡 + 重试。
- [ ] 预览条数/收支/跳过/退款统计与文件一致。
- [ ] 预览的「其中退款相关 N 条」文案与实际入库一致（退款收入记入收入，被退款的原支出标记为「已退款」、不再计入支出）。
- [ ] 被标「已退」的原支出不再计入支出；部分退款的原支出照常全额计入支出。
- [ ] 账户为空时不能导入；选择账户后能导入。
- [ ] 完成后显示成功/重复条数与账户名。
- [ ] 继续导入回到阶段 0；返回后状态清空。
- [ ] 分享文件进入能直接看到预览。
- [ ] 1.25 字体下阶段条、预览行、按钮不裁。
