# 04 · 统计

四个 tab 中的 tab 2。结构：共享结余封面 → 周期工具条 → `01` 支出节奏柱状图 → `02` 分类预算圆环（吸顶）→ 预算对比清单。没有 FAB。

**两套口径，别混**：
- 封面与 `01` 支出节奏 = **账面支出**（含被标「已退款」的原支出、不折算 AA，不做减法）；
- `02` 分类占比圆环、「实际支出」读数与**预算对比清单** = **Σ(未被标「已退款」的支出)，AA 按 m ÷ n 折算、「不计入预算」仍按全额**；
  退款按原支出所属期归属，退款收入不冲减支出（见 [退款关联](12-退款关联.md)）。
  圆环、预算对比清单、`periodSpendingTotal` 三者同一口径：**清单各行「实际」之和 = 实际支出总额**，
  行占比加起来是 100%；头部合计也直接取实际支出总额。
  > 预算口径（不计入预算算 0）只用于**首页预算卡 / 分类剩余预算**（`observeBudgetSpendingTotal` /
  > `observeBudgetCategorySums`）；统计页不再使用预算口径的分类金额。

源码：`app/src/main/java/com/controleco/app/ui/stats/StatsScreen.kt`（约 1085 行）
共享：`ui/transactions/BalanceCard.kt`、`ui/transactions/CoverStyleStore.kt`、`ui/common/PeriodControls.kt`

## 3. 页面骨架

```
Column(fillMaxSize)
  EcoTopBar(micro="INSIGHTS / {MON}", title="统计", action="{年} / {月}")
  LazyColumn(
    state,
    pointerInput 空白点击 -> 取消圆环选中,
    contentPadding = PaddingValues(bottom = ecoBottomContentPadding(extra=180.dp))
  )
    item cover:  Box(padding 22/6) BalanceCard(showEdit=false)
    item toolbar: StatsToolbar
    item trendHead: EcoSectionHead("01", "每日支出"/"月度支出", "DAILY"/"MONTHLY")
    item trend: TrendCard
    stickyHeader donutSticky: Column(background paper)
        EcoSectionHead("02", "分类预算与占比", "BUDGET / ACTUAL")
        DonutCard
    item ratio: RatioCard
  if (showPicker) PeriodPickerSheet
```

`extra = 180.dp` 是**有意留的滚动余量**：让 `02` 圆环能真正吸顶；滚到最底会看到一段空白，这是已知取舍。

## 5. 状态与数据流

### 只读 Flow

| 状态 | 用途 |
| --- | --- |
| `month` | 当前周期 |
| `periodMode` | 月/年 |
| `currentAccountingMonth` | 判断是否当前周期 |
| `monthStartDay` | 会计月起始日 |
| `periodTotals` | 收入/支出合计（账面） |
| `periodSpendingTotal` | 本期**实际支出**：Σ(未被标「已退款」的支出)，AA 按 m ÷ n 折算、「不计入预算」按全额 |
| `periodCategorySums` | 本期分类实际支出：同口径按分类分组，**各分类之和恒等于总支出**，不可能为负；**圆环与预算对比清单共用** |
| `periodRows` | 本期流水（柱状图） |
| `categoryBudgets` | 分类预算 |
| `categories` | 分类名/图标/类型 |
| 封面 5 个 Flow | 与账单共享 |

`rows / totals / byCategory / spendingTotal` 任一为 null → 整页 `return`。

### 派生

- `expense` / `income` / `balance`：从 `periodTotals` 取（账面，封面与柱状图用）。
- `spendingTotal`：`periodSpendingTotal`，**`02` 的总支出**（Σ(未被标「已退款」的支出)，AA 按 m ÷ n、「不计入预算」按全额）。
  它与首页 `homeSpent`（预算口径，还会把「不计入预算」算 0）只在有「不计入预算」账单时不同。
- `isCurrentPeriod`：月模式比 `YearMonth`，年模式比年份。
- `bars`：`ChartMath.monthBars(rows, month, monthStartDay)` 或 `yearBars(rows, month, monthStartDay)`（账面）。
  年视角按**会计月**分桶（`MonthPeriod.year` 的 12 个会计月）；首日 ≠ 1 时次年 1 月 1 日到首日前的账单
  归入 12 月桶，不能按 `date.monthValue` 分桶（会静默丢账单、柱子合计小于封面）。
- `barGrow`：柱状图入场进度（`Animatable`，**页面级**）。`LaunchedEffect(bars, animationsEnabled)` 驱动；
  切页（本页离开组合再回来 = 重建）或 `bars` 变（换周期/新数据）才重播，上下滑动不重播。
- `defaultBarIndex`：当前周期取今天对应的柱（年视角取今天所属**会计月**，首日≠1 时可能是 12 月桶）；历史周期取支出最高柱。
- `selectedBar`：页面状态，`remember(bars)` 重置。
- `slices`：`ChartMath.mergeSlices(分类实际支出, 分类预算)`；实际支出按 AA 折算（「不计入预算」仍全额），年模式预算 ×12。
  分类金额不可能为负，切片不需要 `coerceAtLeast(0)` 兜底。
- `sliceColors`：与分类图标同色（自定义颜色优先，否则从 palette 选“离已用色最远”）。
- `ratioRows`：`buildRatioRows(categoryBudgets, categories, byCategory, mode)`，第三个参数传
  **分类实际支出**（`periodCategorySums`，不计入预算仍全额、AA 按 m ÷ n），与圆环同一口径；
  **设了预算的分类 ∪ 本期有账单的分类**（没设预算的记 0）；
  年模式预算 ×12；排序 实际降序 → 预算降序 → 名字升序。`buildRatioRows` 过滤 `totalCents <= 0`。
  清单各行「实际」之和 = `periodSpendingTotal`，头部合计也用它，所以行占比加起来是 100%。
- `selectedSlice`：圆环/清单共享的选中分类；点页面空白取消。

### 交互

- 左右箭头：`vm.prevPeriod()` / `nextPeriod()`。
- 点周期文字：`PeriodPickerSheet`。
- 月/年分段：`vm.setPeriodMode(...)`。
- 点柱/滑柱：`selectedBar`；卡片头部读数跟随。
- 点环/图例行：选中分类；再点空白取消。
- 在 `LazyColumn` 外层 `pointerInput` 检测空白点击，清空选中；环和行自己消费点击。

## 8. 坑与验收

**坑**

1. **只有一个圆环**。历史上的双环/环心数字/图例都已废弃；`CategoryDonut` 必须 `singleRing=true`、`showCenterLabels=false`。不要再加第二个环。
2. 底部 `extra=180.dp` 是为了吸顶预留的滚动余量，不是 bug；删掉会让 `02` 在短列表上无法吸顶。
3. `stickyHeader` 的背景必须是 `c.paper`，否则吸顶时会透出下方内容。
4. 年模式的预算要 **×12**（切片和对比都是），漏乘会让占比全错。
5. 圆环颜色必须与分类图标同色；不要按 `slices` 下标轮询 palette。
6. 点空白取消选中依赖 `LazyColumn` 外层 `pointerInput`；给卡片加全屏 `clickable` 会截断它。
7. `ConclusionCard` / `StatsSummaryLine` / `RatioSide` 等是死代码；改页面时不要误以为它们在渲染。
8. 统计页复用账单封面状态；在账单页换图后统计页立即变，不要另存一份。
9. `PeriodPickerSheet` 的年选择只改年份、保留当前月；沿用 `vm.setMonth` 的语义。
10. **柱状图入场进度不要 `remember` 在 `ExpenseBarChart` 里**。它是 `LazyColumn` 的一个 item，
    滑出屏幕就被销毁；进度存在 item 内部 → 滑回来从 0 重播（用户反馈的 bug）。
    进度由 `StatsScreen` 的 `barGrow` 持有、以 `grow: () -> Float` 传给组件，只有切页（本页重建）
    或 `bars` 变（换周期）才重播；上下滑动无论可见与否都不重播。
    传 lambda 而不是 `Float` 值：状态读取落在 Canvas 的绘制阶段，每帧只重画不重组。
11. **预算对比清单要含"有账单但没设预算"的分类**（预算 ¥0、占比 0%）。只遍历
    `categoryBudgets` 会让这些分类整行消失（用户反馈的 bug）。`buildRatioRows` 的口径与圆环的
    `mergeSlices` 对齐：设了预算的支出分类 ∪ 本期有账单的支出分类；收入分类两边都不收。
12. **圆环 / 总支出 / 预算对比清单都是「实际支出」口径**：Σ(未被标「已退款」的支出)，AA 按 m ÷ n 折算、
    「不计入预算」仍按全额。三者必须同口径——清单各行之和 = 头部合计 = `periodSpendingTotal`，
    行占比加起来 100%；**不要**为了"和首页对齐"把清单改回预算口径（「不计入预算」算 0），
    那会让头部与行对不上、占比不满 100%（用户已明确要求统一为实际支出口径）。
    `transactions.refundLinkId` 已随 DB v13 删除，不要再引入任何配对/关联/扣减逻辑。
13. **退款收入永远计入收入，不影响支出**。退款收入分类固定为「退款」、`refundMark = REFUND_INCOME`，
    不会冲减任何支出，也不进 `02` 的分类；支出侧只有「原支出被标 `REFUNDED_EXPENSE` 后不再计入」这一条规则。
14. **分类金额不可能为负**：退款按原支出所属期归属，只会把某笔原支出整体剔除，不做减法。
    `buildRatioRows` 过滤 `totalCents <= 0`；`ratioPercent` 不再处理负分子；切片也不再需要 `coerceAtLeast(0)` 兜底。
15. **年视角柱状图按会计月分桶**：`yearBars(rows, month, startDay)` 用 `MonthPeriod.of(date, startDay).start`
    的月份归属算桶，不能用 `date.monthValue`。首日 ≠ 1 时会计年尾部含次年 1 月初的账单，
    按自然月分桶会把它们丢掉（柱子合计 < 封面/实际支出）。`defaultBarIndex` 的年模式也要用同一个映射。
