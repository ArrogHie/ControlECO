# 21 · 设置 · 开发者功能

面向排障的入口页：手动触发测试通知/悬浮卡、待确认/捕获日志/保活、调试开关、溯源开关与记录。

源码：`app/src/main/java/com/controleco/app/ui/settings/SettingsDeveloperScreen.kt`（约 175 行）
共享：`SettingsPage`、`SettingsSection`、`SettingsPane`、`SettingsRow`、`SettingsSwitchRow`、`SettingsValueRow`

---

## 1. 路由与入口

- 路由：`settings/developer`。
- 进入：设置首页 → `02 系统` →「开发者功能」。
- 离开：
  - 待确认 → `pending`
  - 捕获日志 → `captureLog`
  - 保活与自启动 → `keepAlive`
  - 溯源记录 → `captureTrace`
  - 返回。

## 5. 状态与数据流

### 只读

- `lastCaptureAt`：0 → `尚未收到`，否则 `formatTimestamp`。
- `pendingCount`：0 → `没有等待处理的条目`，否则 `N 笔等待处理`。
- `debugCaptureAll`、`debugCaptureAllPages`。
- `traceEnabled`、`traceCount`。

### 手动测试

- `vm.scheduleNotifyTest(toast())`：20 秒后模拟动账通知。
- `vm.showOverlayTest(0L, toast())`：立即悬浮卡。
- `vm.showOverlayTest(20_000L, toast())`：20 秒后悬浮卡。
- `toast()` 固定 `EcoPillTone.Blue`。

### 调试开关

- `setDebugCaptureAll`：记录所有应用通知（绕过监听范围）。
- `setDebugCaptureAllPages`：捕获所有页面。
- release 也保留，不依赖 `BuildConfig.DEBUG`。

### 溯源

- `setTraceEnabled`：开启后每次入账相关捕获留原文，最多 1000 条；关闭零写入。
- `traceCount == 0` → trail `暂无`，否则 `N 条`。

## 9. 坑与验收

**坑**

1. 三个测试动作的延迟不同（20s / 0 / 20s）；不要把“立即”也改成延迟。
2. 测试 Toast 固定 Blue；改色调前确认与其它反馈一致。
3. 调试开关在 release 也保留；不要用 `BuildConfig.DEBUG` 包起来。
4. “记录所有应用的通知”会绕过监听范围；这是排障用，不是普通用户开关。
5. 溯源默认关；关闭时零写入，但历史记录仍可看。
6. `traceCount` 为 0 时 trail 是 `暂无`，不是 `0 条`。
7. 本页没有“清空日志/清空溯源”的入口；清空在各自子页顶栏。
8. 待确认副标是“等待处理”的条数，不是总数。

**验收**

- [ ] 三个测试动作都能触发，延迟正确。
- [ ] 待确认/日志/保活/溯源入口都能到达。
- [ ] 最近捕获、待确认数量、溯源条数正确。
- [ ] 两个调试开关与溯源开关持久化。
- [ ] 1.25 字体下长标题/副标不裁。
