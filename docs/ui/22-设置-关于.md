## 1. 路由与入口

- 路由：`settings/about`。
- 进入：设置首页 → `关于` →「关于 我ECO」。
- 离开：
  - 「在浏览器中打开仓库」→ 系统浏览器

  - 「开源许可」→ 本页 `EcoSheet`
  - 返回。

## 5. 状态与数据流

- `showLicenses`：许可 sheet 开关。
- `checking`：检查更新进行中；trail 变 `检查中…`、chevron 隐藏、点击被忽略。
- `BuildConfig.VERSION_NAME` / `VERSION_CODE` / `DEBUG`：版本与构建类型。
- `GITHUB_REPO_PATH = "ArrogHie/ControlECO"`；`GITHUB_REPO_URL` 由它拼出。
- 检查更新：`AppUpdate.checkNow(context) { message -> ... }`
  - `null` → `发现新版本，正在打开更新…`（Blue）
  - `startsWith("检查失败")` → Warn
  - 其它 → Good

## 9. 坑与验收

**坑**

1. 「检查更新」用的是 `AppUpdate.checkNow`，不是 `vm.checkUpdateNow`；两条路径都存在，别混。
2. `checking` 时必须禁用重复点击并隐藏 chevron；否则会重复检查。
3. 下载/安装不在本页：`AppUpdate` 发现新版本后写 `updateAvailable`，由 `MainActivity` 的 `UpdateAvailableDialog` 处理；不要在本页加下载进度。
4. 仓库 URL 由 `GITHUB_REPO_PATH` 拼出；改一处即可，但显示文案 `ArrogHie / ControlECO` 也要同步。
5. hero 是固定深色，前景用 `HERO_*` 常量；不要换成 `eco.ink/paper`。
6. 许可 sheet 用 `EcoSheet`（默认可滚）；列表较长时依赖它的滚动，不要再套 `verticalScroll`。
7. 页脚前后空格是设计的一部分（`•  ...  •`），不要 trim。
8. 隐私承诺是产品文案，不要擅自删减成一句。

**验收**

- [ ] hero、隐私、版本、仓库、页脚完整。
- [ ] 检查更新各分支 Toast 正确，检查中不可重复点。
- [ ] 开源许可 sheet 可滚、可关闭。
- [ ] 仓库能在浏览器打开；失败有 Toast。
- [ ] 版本号/构建类型与 BuildConfig 一致。
- [ ] 1.25 字体下隐私长文、版本行、页脚不裁。
