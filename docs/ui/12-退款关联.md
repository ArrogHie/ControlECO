# 12 · 退款处理

当前实现不保存退款关联 ID，数据库版本保持 14。业务规则见[业务与数据模型](../业务与数据模型.md)。

## 入口与路由

- 新捕获的退款无论是否有金额，都先进入「待处理」。通知与列表「选择原账单」打开 `refundLink/{pendingId}`。
- 更新前已经入账、带 `refundPending` 的退款仍显示在待处理列表，打开 `refundLegacy/{refundId}`。
- 旧版无 ID 的退款通知打开待处理列表，不提供无来源的退款登记入口。
- 已入账支出的编辑页提供「退款该账单」或「撤销退款」。

## 候选页

源码：`ui/refund/RefundLinkScreen.kt`，纯筛选：`RefundFilters.kt`。

- 标题「选择被退款的账单」。有捕获金额时显示退款金额，只列同金额、未退款的支出，提供开始／结束日期。
- 没有捕获金额时显示所有未退款支出，提供商户、最低／最高金额、开始／结束日期。
- 不受当前会计周期、60 天或 50 条限制，列表使用 LazyColumn。
- 商户忽略空白、大小写；金额为闭区间；日期按设备本地时区，包含起止两天；两端填反自动交换，留空表示不限。
- 点击「重置」清空所有筛选。筛选条件为 AND，空态「暂无可选账单」。不添加说明小字。
- 点击候选行立即提交；提交期间防止重复执行。成功提示「已退款」并返回；失败保留页面并显示错误。
- 捕获无金额时按原支出全额退款。有金额时必须与原支出金额一致。没有部分退款金额表单，也没有「记为收入」旁路。
- 已处理或丢弃的通知再次进入显示「退款已处理」，不会重复生成收入。

## 写入

- 新捕获退款通过 `refundCaptured(pendingId, expenseId)` 在同一事务中生成收入、标记支出、完成待处理条目。
- 旧版待处理退款通过 `handlePendingRefund(refundId, expenseId)` 修改已有收入及原支出的标记，不重复生成收入。
- 退款收入归固定「退款」分类，不进入待处理。

## 编辑页与手工新增

- 普通支出显示「退款该账单」；已退款支出显示「撤销退款」。操作针对已保存账单；表单有未保存修改时禁用退款操作。
- 退款生成同额、同账户收入。撤销时删除原支出之后第一笔同金额「退款」收入，恢复支出标记；不保存关联关系。
- 「记一笔」与普通账单编辑不可选择收入「退款」分类；已存在的退款收入编辑仅保留该分类。
- 退款收入及已退款支出不可在编辑页切换收入／支出方向。

## 验证

自动测试 `RefundFiltersTest` 覆盖同额限制、未退款支出、跨年与超过 50 条、商户／金额／日期组合、包含日期全天、反向区间和开放边界。设备端仍需检查通知直达、键盘与日期选择器、长列表及重复点击处理。
