# 12 · 退款关联

微信「退款到账」通知不带金额，无法自动入账。用户在这里选一笔被退款的支出，生成退款收入（可改金额，支持部分退款），并把原支出标记「已退款」；两笔记录之间**不建立任何关联**。

> **两条互补的路径，别混**：
> 1. **本页**：从「无金额的退款通知」进来 → **生成**一条退款收入，并把用户选中的那笔支出标「已退款」（两笔记录之间**不写任何关联**）。
> 2. **待确认账单**（[11](11-待确认.md)）：退款收入**已经在账上**（捕获来的），但还没处理（`refundPending = 1`） →
>    在那里选中被退款的支出，或「记为收入」。详见第 7 节。

源码：`app/src/main/java/com/controleco/app/ui/refund/RefundLinkScreen.kt`（约 278 行）

---

## 1. 路由与入口

- 路由：`refundLink`。
- 进入：微信退款到账通知（`CaptureCenter.ROUTE_REFUND_LINK`）；也可从通知栏点击进入。
- 离开：返回；生成成功后停留本页，候选列表移除该笔。
- 本页没有“新建/编辑退款”的其它入口。

## 5. 状态与数据流

### 本地

- `rows: List<TransactionRow>`，`loading`。
- `linking: TransactionRow?`。

### 加载

`LaunchedEffect(Unit)` → `vm.refundCandidates()`，然后 `loading = false`。

候选口径（由 VM 决定）：**近 60 天、还没标「已退款」的支出**。

### 登记

`LinkRefundSheet`：

- `amountText` 默认 `Money.formatCents(row.amountCents)`。
- 校验：
  - 空/≤0 → `请输入有效金额`。
  - `> 原支出` → `退款金额不能超过原支出`。
- `vm.registerRefund(row.id, amountCents)`：
  - 成功：原支出标记 `REFUNDED_EXPENSE`（已退款）；本页候选移除该行；`EcoToast("已生成退款收入")`；关闭 sheet。
  - 失败：错误显示在 sheet 内，不关闭。
  - 生成的退款收入：`type=INCOME`、`refundMark=REFUND_INCOME`、分类固定为收入「退款」、入**原支出账户**、时间取登记时刻，
    `refundPending = false`（**不会**再进「待确认账单」），**不写任何关联**。

### 结果

- 生成一条退款收入流水（分类「退款」），并把那笔原支出标 `REFUNDED_EXPENSE`；两笔记录之间**不写任何关联**。
- 原支出行在账单中显示 `已退` 标记；退款收入显示 `退款` 标记。
- 两者都留在流水里：被标记的原支出**不再计入支出**，退款收入**始终计入收入**（「显示退款记录」开关已删除）。
- **分类预算**：按「未被标已退款的支出之和」计算，不做减法；标记后原支出所属分类的金额随之减少。
  预算口径还会把「不计入预算」算 0（AA 按 m ÷ n），所以「各分类之和 = 首页本月支出」成立；
  统计页 `02` 的圆环是**实际支出**口径（AA 也按 m ÷ n，但「不计入预算」仍全额），
  两者只在有「不计入预算」账单时不同，这是设计口径。

## 7. 待确认账单里的退款（另一条路径）

通知/页面/短信捕获来的退款收入已经在账上，但还没处理（`refundPending = 1`）时，
它会出现在 [11-待确认账单](11-待确认.md) 的同一个列表里（**不单独分区**），带 `待处理` 胶囊。

### 数据

- `transactions.refundPending = 1` 的退款收入。
- 通知/页面/短信捕获的退款收入默认 `refundPending = 1`；**账单导入的退款 = 0**（账单自己已经把该标的都标好了，不进待确认）；
  **升级前已入库的历史退款 = 0**（迁移 v12 默认值），不进待确认、也不弹提示。

### 两种处理

1. **选择原账单**：点行（或「选择原账单」）→ `vm.refundExpenseCandidates(金额)` →
   只列**同金额**、且还没标「已退款」的支出 → 点一行即完成
   `vm.handlePendingRefund(refundId, expenseId)`。
   - 选中后把那笔支出标 `REFUNDED_EXPENSE`（**两笔记录之间不写任何关联**）。
   - 处理后 `refundPending = 0`，那笔支出不再计入支出与分类预算。
2. **记为收入**：`vm.markRefundAsIncome(refundId)` → `refundMark = NONE`、
   `refundPending = 0`。这笔钱**按普通收入记账**（照常计入收入）；对应的支出保持原样，**仍计入支出**。

### 约束

- 候选只列**同金额**、且还没标「已退款」的支出；一笔支出被标「已退款」后不再出现在候选里
  （`markExpenseRefunded` 只对未标记的生效）。
- 金额对不上（部分退款、跨平台同额不同单）时，候选列表为空——这时只能「记为收入」。

## 10. 坑与验收

**坑**

1. 退款金额**不能超过原支出**；部分退款是合法场景，不要强制必须等于原金额。
2. 原支出被标记「已退款」后不能再被选中；候选列表应移除。
3. 候选行的分类 tile 是**带底色**的 38dp（与账单行 `bare=true` 不同）。
4. 生成成功发 `EcoToast` 并关闭 sheet；提交中禁止 dismiss。
5. `loading` 与空态要分开：加载中不能先显示“暂无可选的支出”。
6. 被标「已退款」的原支出**不再计入支出与分类预算**，退款收入**始终计入收入**，不存在"显示开关"；
   预算口径是「未被标已退款的支出之和」再把「不计入预算」算 0（AA 按 m ÷ n），与账单页的账面口径不同，不要相互套用。
7. 通知进入时可能没有候选（已处理/超 60 天）；空态要能解释原因。
8. 金额输入用 `EcoMoneyField`；不要换成普通 `EcoField`。
9. **本页生成退款时不需要写任何关联**：生成的退款收入 `refundPending = false`，不会冒到待确认里；
   只要把那笔原支出标上 `REFUNDED_EXPENSE`，它就不再计入支出与分类预算。
10. `refundPending` 只对新捕获的退款置 1（导入的退款是 0）；**迁移时历史退款必须是 0**，
    否则升级后一次冒出几十条待处理（用户明确要求不打扰）。

**验收**

- [ ] 加载/空/列表三态正确。
- [ ] 默认金额 = 原支出；可改小；超过原支出被拒。
- [ ] 生成后退款收入出现，原支出标记「已退」，候选移除，分类预算按「未退款支出之和」变化。
- [ ] 重复进入不会再次列出已退款支出。
- [ ] 生成的退款**不**出现在「待确认账单」。
- [ ] 待确认里点退款 → 只列同金额、还没标已退款的支出；点一行即把那笔支出标「已退款」；列表消失。
- [ ] 「记为收入」后原支出保持原样、照常计入本月支出与分类预算。
- [ ] 1.25 字体下金额/商户/详情不裁。
- [ ] 深色模式下陶土/玉绿标记可读。
