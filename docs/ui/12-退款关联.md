# 12 · 退款关联

微信「退款到账」通知不带金额，无法自动入账。用户在这里选一笔被退款的支出，生成退款收入（可改金额，支持部分退款），并把原支出标记「已退款」。

> **两条互补的路径，别混**：
> 1. **本页**：从「无金额的退款通知」进来 → **生成**一条退款收入，天然知道原支出，直接写上 `refundLinkId`。
> 2. **待确认账单**（[11](11-待确认.md)）：退款收入**已经在账上**（导入/捕获），但还没指认原支出 →
>    在那里点选同金额的支出，或「记为收入」。详见第 7 节。

源码：`app/src/main/java/com/controleco/app/ui/refund/RefundLinkScreen.kt`（约 278 行）

---

## 1. 路由与入口

- 路由：`refundLink`。
- 进入：微信退款到账通知（`CaptureCenter.ROUTE_REFUND_LINK`）；也可从通知栏点击进入。
- 离开：返回；关联成功后停留本页，候选列表移除该笔。
- 本页没有“新建/编辑退款”的其它入口。

## 5. 状态与数据流

### 本地

- `rows: List<TransactionRow>`，`loading`。
- `linking: TransactionRow?`。

### 加载

`LaunchedEffect(Unit)` → `vm.refundCandidates()`，然后 `loading = false`。

候选口径（由 VM 决定）：**近 60 天、未退款、支出**。

### 关联

`LinkRefundSheet`：

- `amountText` 默认 `Money.formatCents(row.amountCents)`。
- 校验：
  - 空/≤0 → `请输入有效金额`。
  - `> 原支出` → `退款金额不能超过原支出`。
- `vm.linkRefund(row.id, amountCents)`：
  - 成功：原支出标记 `REFUNDED_EXPENSE`（已退款）；本页候选移除该行；`EcoToast("已生成退款收入")`；关闭 sheet。
  - 失败：错误显示在 sheet 内，不关闭。
  - 生成的退款收入：`type=INCOME`、`refundMark=REFUND_INCOME`、分类固定为收入「退款」、入**原支出账户**、时间取关联时刻，
    并直接写入 `refundLinkId = 原支出 id`（`refundPending = false`，**不会**再进「待确认账单」）。

### 结果

- 生成一条退款收入流水（分类「退款」），并**指到被退款的原支出**（`transactions.refundLinkId`）。
- 原支出行在账单中显示 `已退` 标记；退款收入显示 `退款` 标记。
- 两者**始终**计入流水与汇总（「显示退款记录」开关已删除）：原支出照常计入支出，退款收入计入收入。
- **分类预算**：这笔退款从原支出所属分类里扣（统计页 `02` 与首页分类条都是 支出 − 退款）；
  总支出与首页「本月已花」一致。

## 7. 待确认账单里的退款（另一条路径）

退款收入已经在账上（账单导入 / 通知 / 页面捕获），但还不知道退的是哪一笔支出时，
它会出现在 [11-待确认账单](11-待确认.md) 的同一个列表里（**不单独分区**），带 `待关联` 胶囊。

### 数据

- `transactions.refundPending = 1` 且 `refundLinkId IS NULL` 的退款收入。
- 新导入/新捕获的退款收入默认 `refundPending = 1`；
  **升级前已入库的历史退款 = 0**（迁移 v12 默认值），不进待确认、也不弹提示。

### 两种处理

1. **关联原账单**：点行（或「关联原账单」）→ `vm.refundExpenseCandidates(金额)` →
   只列**同金额**的支出（已被别的退款指名的排除）→ 点一行即完成
   `vm.linkRefundToExpense(refundId, expenseId)`。
   - 全额退款（`退款 ≥ 原支出`）顺带把原支出标 `REFUNDED_EXPENSE`；部分退款保持原标记。
   - 关联后 `refundPending = 0`，该退款从原支出分类里扣。
2. **记为收入**：`vm.markRefundAsIncome(refundId)` → `refundMark = NONE`、`refundLinkId = NULL`、
   `refundPending = 0`。这笔钱**按普通收入处理，不再从预算里减**（首页「本月已花」与分类都不会减它）。

### 约束

- 一笔支出**只允许被一笔退款指名**（`countRefundsLinkedTo` 校验，候选查询也已排除）。
- 金额对不上（部分退款、跨平台同额不同单）时，候选列表为空——这时只能「记为收入」。

- 顶栏：`REFUND LINK` / `选择被退款的账单`。
- 说明：`微信「退款到账」通知不带金额，无法自动入账。选择对应的支出记录后，会生成一条退款收入（可改金额以支持部分退款），并把原支出标记为「已退款」。`
- 加载：`加载中…`。
- 空态：`暂无可关联的支出` / `近 60 天没有可关联的支出记录。退款收入默认等于原支出金额。`
- 行：金额 `-X`、`商户`、`分类 / 账户 / 日期`；未命名时 `未命名支出`。
- 页尾：`仅显示近 60 天、未退款的支出；退款收入默认等于原支出金额。`
- sheet：`登记退款`；`原支出 X，商户，日期`；`退款金额（元）`；`默认等于原支出；可改成更小的金额以支持部分退款。`；`取消`；`生成退款收入`；`处理中…`；错误 `请输入有效金额`、`退款金额不能超过原支出`。

## 10. 坑与验收

**坑**

1. 退款金额**不能超过原支出**；部分退款是合法场景，不要强制必须等于原金额。
2. 原支出被标记「已退款」后不能再次关联；候选列表应移除。
3. 候选行的分类 tile 是**带底色**的 38dp（与账单行 `bare=true` 不同）。
4. 关联成功发 `EcoToast` 并关闭 sheet；提交中禁止 dismiss。
5. `loading` 与空态要分开：加载中不能先显示“暂无可关联”。
6. 退款收入与退款支出**永远计入**流水/汇总，不存在"显示开关"；预算口径是本期的「支出 − 退款到账」，与账单页的账面口径不同，不要相互套用。
7. 通知进入时可能没有候选（已处理/超 60 天）；空态要能解释原因。
8. 金额输入用 `EcoMoneyField`；不要换成普通 `EcoField`。
9. **本页生成退款时一定要写 `refundLinkId`**。漏了它，退款会被当成"未关联"冒到待确认里，
   而且分类预算扣不到正确分类。
10. `refundPending` 只对新导入/新捕获的退款置 1；**迁移时历史退款必须是 0**，
    否则升级后一次冒出几十条待处理（用户明确要求不打扰）。

**验收**

- [ ] 加载/空/列表三态正确。
- [ ] 默认金额 = 原支出；可改小；超过原支出被拒。
- [ ] 生成后退款收入出现，原支出标记「已退」，候选移除，分类预算按净额变化。
- [ ] 重复进入不会再次列出已退款支出。
- [ ] 生成的退款**不**出现在「待确认账单」。
- [ ] 待确认里点退款 → 只列同金额支出；点一行即关联；列表消失。
- [ ] 「记为收入」后不再从预算扣，首页「本月已花」相应增大。
- [ ] 1.25 字体下金额/商户/详情不裁。
- [ ] 深色模式下陶土/玉绿标记可读。
