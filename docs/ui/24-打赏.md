# 24 · 打赏

个人页底排「打赏」圆钮的目标页：微信 / 支付宝两张收款码，点图全屏预览，可把原图保存到系统相册。

源码：`app/src/main/java/com/controleco/app/ui/profile/RewardScreen.kt`（约 450 行）
相册落盘：`app/src/main/java/com/controleco/app/util/AlbumSaver.kt`
依赖：`EcoTopBar`、`EcoPane`、`EcoPageLead`、`EcoPageNote`、`EcoPrimaryButton`、`EcoToast`、`ecoPressable`、`EcoIcons`（`Gift` / `Wallet` / `Download` / `Image` / `Close`）、`AlbumSaver`、`AppLog`

> 2026-10-23 之前这里是个人页里的 `RewardDialog` 弹窗（两张码并排、约 150dp 见方）。
> 改成独立页后码图接近整宽，并补上了「预览 + 保存到相册」。旧弹窗与 `RewardQr` 已删除，
> 不要再按 `05-个人.md` 的旧描述去找 `RewardDialog`。

## 1. 路由与入口

- 路由：`reward`（`AppNav.kt` 的 `NavHost`）。
- 进入：个人页底排陶红「打赏」圆钮 → `RewardTile.onClick` → `ProfileScreen` 的 `onOpenReward` → `navigate("reward")`。
- 离开：
  - 顶栏返回 → `popBackStack()` 回个人页。
  - 点码图 → 本页全屏预览 Dialog（不换路由）。
  - 预览里「保存到相册」→ 写 `Pictures/易控钱包`，留在预览层，只有 Toast 反馈。
  - 保存失败 / 没授权 → Toast，不弹二级对话框。

## 5. 状态与数据流

全部是页面本地状态，不碰 VM：

| 状态 | 含义 |
| --- | --- |
| `previewing: RewardCode?` | 当前全屏预览的码；null 关闭预览 |
| `savingKey: String?` | 正在保存的那张（`wechat` / `alipay`）；非空时按钮显示「保存中…」并禁用 |
| `pendingKey: String?` | 等待存储权限授权的那张（只有 Android 8/9 用） |

保存流程：

1. `requestSave(code)`：`AlbumSaver.needsLegacyPermission()` 且 `!hasLegacyPermission(context)` → 记 `pendingKey` 并 `launch(WRITE_EXTERNAL_STORAGE)`；否则直接 `performSave`。
2. `performSave(code)`：置 `savingKey` → `Dispatchers.IO` 里 `AlbumSaver.saveRawResource(context, resId, fileBase, extension)` → 回主线程清状态。
3. 成功 Toast「已保存到相册」（Good），失败 `AppLog.w("Reward", ...)` + Toast「保存失败，请检查系统相册权限」（Warn）。
4. **保存结束（成功或失败）若预览正开着，先收起预览**：`EcoToast` 挂在 Activity 内容里，会被全屏 Dialog 挡住。
5. 权限回调：`granted && code != null` → 继续保存；拒绝 → Toast「未授予相册权限，无法保存」。

`AlbumSaver.saveRawResource`：

- Android 10+：`MediaStore.Images.Media` 插入 `DISPLAY_NAME` / `MIME_TYPE` / `RELATIVE_PATH=Pictures/易控钱包/` / `IS_PENDING=1` → 写字节 → `IS_PENDING=0`；失败删掉占位条目。
- Android 8/9：`Environment.getExternalStoragePublicDirectory(Pictures)/易控钱包` 直写文件 + `MediaScannerConnection.scanFile`。
- 写的是 `resources.openRawResource` 的**原始字节**（微信 PNG / 支付宝 JPG），不做 Bitmap 二次压缩。
- 重名递增：`名字.png` → `名字-2.png` → `名字-3.png`（MediaStore 查同目录已有名；旧路径用 `uniqueFile`）。

清单：`WRITE_EXTERNAL_STORAGE` 带 `android:maxSdkVersion="28"`，只有 8/9 会请求；10+ 不申请。

## 9. 坑与验收

**坑**

1. **保存必须写原始资源字节**（`openRawResource` → 输出流）。改成 `Bitmap` 解码再 `compress` 会把二维码点阵压糊，
   扫不出来；也不要转成 `webp`。
2. `RewardCode.extension` 必须与 `drawable-nodpi` 里的真实格式一致（微信 **png**、支付宝 **jpg**）。
   MIME 由扩展名推导（`AlbumSaver.mimeOf`），写错相册会把它当未知图片。
3. **只有 Android 8/9 需要 `WRITE_EXTERNAL_STORAGE`**；清单里限定 `maxSdkVersion=28`。
   不要给 10+ 也去申请——targetSdk 35 下该权限在 10+ 直接不生效，还会白弹一次系统框。
4. MediaStore 插入后如果写文件失败，要 `delete(uri)` 清掉占位条目（已实现），否则相册里会出现 0 字节的坏图。
5. 码图容器必须是**纯白底 + 内边距**：二维码四周的静区被卡片底色吃掉就识别率骤降。
6. 预览页**不做缩放手势**（产品口径：整宽已够看，手势会和「点空白关闭」抢事件）。
   图片容器上的 `clickable {}` 是用来吞点击的，删掉它会导致点图即关闭。
7. 品牌色固定，暗色下抬亮；不要图省事换成 `eco.blue`，微信/支付宝在视觉上要能分辨。
8. 保存动作在 `savingKey != null` 时禁用并显示「保存中…」，避免重复点按插多条相册记录。
9. 旧弹窗 `RewardDialog` / `RewardQr` 已删；`ProfileScreen` 里只保留 `BottomRow(onReward = onOpenReward)`。
10. 预览是 `Dialog` 独立窗口，**全局 `EcoToast` 会被它挡在后面**。所以保存结束必须收起预览再提示；
    以后若要在预览里加别的结果反馈（如「已保存」行内文案），不要依赖页面级 Toast。
