# 07 · 编辑交易

账单点行、捕获通知「已记入一笔账」、溯源「查看对应账单」都会进入本页。它同时承担“新增但走完整表单”的兜底（`txId <= 0` 时标题仍为编辑记录、按钮为「保存」）。

源码：`app/src/main/java/com/controleco/app/ui/transactions/EditTransactionScreen.kt`（约 400 行）
共享：`TxFormKit.kt`（`TxSectionLabel`、`TxFieldLabel`、`TxSelectField`、`TxDateField`、`TxTypeSegmented`、`TxCategoryChip`、`TxBudgetOptions`）

---

## 1. 路由与入口

- 路由：`edit/{txId}`。
- 进入：
  - 账单点行（`TransactionListScreen` → `onEditTransaction(row.id)`）
  - 通知 `ROUTE_EDIT_PREFIX + id`
  - 溯源页「查看对应账单」
- 离开：
  - 返回 → `popBackStack()`
  - 保存成功 → Toast + `onBack()`
  - 删除成功 → `EcoToast("已删除", Bad)` + `onBack()`
- `txId <= 0` 时按“新增”处理：不加载记录、不显示删除入口。

    Spacer 15

    Spacer 15
    TxSectionLabel("账户与日期") + Row(TxSelectField, TxDateField)
    Spacer 15
    TxSectionLabel("商户与备注") + EcoField 商户 + EcoField 备注

      Spacer 15
      TxSectionLabel("预算")
      EcoPane(16dp, elevation 4, padding 14/2)
        TxBudgetOptions（不计入预算 / AA 支出 + 人数输入）
    if (error) 错误文案

删除确认在页面末尾条件渲染。

「预算」段**只在支出类型下出现**（收入不进预算，没有这两个标记的意义）。

## 5. 状态与数据流

### 只读

`accounts`、`categories`（Flow）。

### 加载

`LaunchedEffect(txId)`：`txId > 0` 时 `vm.transactionById(txId)` → `existing`。

`LaunchedEffect(existing)`：加载完成后回填一次：

- `type`、`amountText`（`Money.formatCents`）
- `categoryId`、`accountId`
- `date`、`timeOfDay`（**保留原时分**）
- `counterparty`、`note`
- `budgetExcluded`
- `aaEnabled` = `aaShares >= BudgetShare.MIN_AA_SHARES`；`aaSharesText` = 人数（未开启时为空串）

### 本地状态

`type`、`amountText`、`categoryId`、`accountId`、`date`、`timeOfDay`、`counterparty`、`note`、
`budgetExcluded`、`aaEnabled`、`aaSharesText`、`error`、`showDeleteConfirm`。

### 默认选择

`LaunchedEffect(accounts, categories, type)`：

- `accountId == null` → 第一个账户。
- `categoryId` 类型 ≠ `type` → 该类型第一个分类。

### 保存

- `ts = LocalDateTime.of(date, timeOfDay)` → 毫秒。
- AA 人数只在「支出 + 勾选 AA」时校验：`BudgetShare.parseShares(aaSharesText)` 需落在 2..99，
  否则 `error = "AA 人数需在 2 到 99 之间"` 并留在本页；其余情况按 0 落库。
- `vm.saveTransaction(txId, type, value, categoryId, accountId, ts, note, counterparty, budgetExcluded, aaShares)`。
  ViewModel 侧对收入强制清掉两个预算标记（`budgetExcluded = false`、`aaShares = 0`），
  并把人数的越界值归一化为 0（见 `BudgetShare.normalizeShares`）。
- Toast：编辑 `已保存修改`；新增 `已记一笔`。
- 成功 `onBack()`。

### 预算口径（只在支出下出现）

| 控件 | 落库 | 口径 |
| --- | --- | --- |
| `不计入预算` 开关 | `budgetExcluded` | 该笔金额不进本期预算支出（首页预算卡 / 分类剩余预算 / 统计页预算对比）；余额、账单金额、统计页「实际支出」不变 |
| `AA 支出` 开关 + 人数 n | `aaShares`（0 = 关） | 计入预算 = 金额 ÷ n，四舍五入到分；n 合法区间 **2..99**，默认 2 |

两者同时勾选：**不计入优先**，计入预算为 0（AA 人数保留在库里，但不再折算）。
具体换算在 `data/budget/BudgetShare.kt`，DAO 里 SQL 与之逐字对应。

### 删除

- 入口：顶栏「删除」或底部「删除这笔记录」。
- `EcoConfirm(title="删除记录", body="确定删除这笔交易吗？删除后不可恢复。", danger=true)`。
- 确认 → `vm.deleteTransaction(id)`：
  - 成功：`EcoToast("已删除", EcoPillTone.Bad)` + `onBack()`。
  - 失败：`error = err`，留在本页。

| --- | --- |

| 账户/日期 | 下拉/日期选择 |

| 保存 | 校验金额/分类/账户（+ AA 人数）→ 写库 → 返回 |
| 删除 | 二次确认 → 删除 → 返回 |

## 9. 坑与验收

**坑**

1. **编辑时必须保留原时分**：只改日期不应该把时间变成 00:00。`timeOfDay` 从原记录加载，保存时与 `date` 组合。
2. 回填用 `LaunchedEffect(existing)` 只做一次；不要在每次重组时覆盖用户输入。
3. 切类型后如果原分类不属于新类型，会自动切到新类型首个分类；这是预期。
4. 顶栏删除与底部删除链接等价，两个入口都要保留（原型如此）。
5. `txId <= 0` 时不要显示删除入口，也不要加载 `transactionById(0)`。
6. IME 弹出时移除 `navigationBarsPadding()`，否则表单底部会多出一段空白。
7. 错误文案只显示一个（`error` 单值）；保存失败与校验失败共用。
8. 删除成功同时发 Bad 色 Toast 并返回；不要改成普通色。
9. 「预算」段只在**支出**下渲染；切到收入时必须同时清掉 `budgetExcluded` / `aaEnabled`，
   否则切回支出会冒出用户看不见的旧勾选（ViewModel 落库时也会再兜一次）。
10. AA 人数只在「支出 + 勾选 AA」时校验；`aaSharesText` 空/非法时才报错，不要把"没勾 AA"当成错误。
11. 不要在这里自己写预算折算公式：口径统一走 `BudgetShare`，SQL（DAO）与 Kotlin 必须一致，
    否则首页预算卡与账单明细会对不上。

**验收**

- [ ] 从账单/通知/溯源进入都能正确回填。
- [ ] 改日期不改时分。
- [ ] 切类型后分类合法；切到收入后不再显示「预算」段。
- [ ] 金额/分类/账户缺失时按钮禁用、错误明确。
- [ ] 支出显示「预算」段；勾 AA 默认 2 人；人数 1 / 100 保存时报「AA 人数需在 2 到 99 之间」。
- [ ] 勾「不计入预算」保存后：账单金额与统计「实际支出」不变，首页本月支出不包含该笔。
- [ ] AA n 人保存后：首页本月支出只增加 金额 ÷ n。
- [ ] 保存后列表/统计/首页数据同步；账单列表出现「不计预算」/「AA n」小标。
- [ ] 删除二次确认文案含「删除后不可恢复」，删除后返回。
- [ ] 1.25 字体下金额、chip、字段、预算行不裁。
- [ ] 系统输入法弹出时保存按钮可达。
