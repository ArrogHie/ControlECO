# 14 · 捕获溯源

开发者功能 → 溯源记录。按时间倒序展示“一次捕获最终怎么处理”：自动入账 / 待确认 / 合并 / 重复 / 退款提醒，并给出对应账单入口与原始快照。

源码：`app/src/main/java/com/controleco/app/ui/debug/CaptureTraceScreen.kt`（约 481 行）

---

## 1. 路由与入口

- 路由：`captureTrace`。
- 进入：设置 → 开发者功能 → 记账溯源。
- 离开：
  - 返回
  - 展开行「查看对应账单」→ `edit/{txId}`
- 清空：顶栏「清空」→ `EcoConfirm`。
- 开关：`记录记账来源` 在开发者功能页，不在本页。

```
Column(fillMaxSize, navigationBarsPadding)
  EcoTopBar(micro="TRACE", title="记账溯源", onBack,
            action = rows 非空 ? "清空" : {})
  LazyColumn(weight 1f, padding 22, bottom 28)
    item lead:
      EcoPageLead(记录中 / 未开启)
      Row("共 N 条（最新在前）" + "点条目展开原文")

      item EcoPane { EcoEmpty("暂无溯源记录"/"暂无记录") }
    else
      itemsIndexed TraceRowCard
    item note: EcoPageNote(留存/1000 条/已丢弃)

```

## 5. 状态与数据流

### 只读

- `traceRows`：最新在前。
- `traceEnabled`：是否开启“记录记账来源”。

### 本地

- `clearAsk`、`expandedId`（单条展开）。

### 行数据 `CaptureTraceRow`

- `trace`：时间、通道、包名、规则、金额、类型、去重键。
- `state`：`BOOKED` / `PENDING` / `DISCARDED` / `NOTICE`。
- `pendingCount`、`linkedId`。

### 处置结果

| outcome | 文案 | 色调 |
| --- | --- | --- |
| `AUTO_ENTRY` | 自动入账 | Good |
| `PENDING` | 待确认入账 | Warn |
| `MERGED_PAGE` | 页面合并回填 | Blue |
| `MERGED_CROSS_APP` | 跨应用同一笔 | Blue |
| `MERGED_CROSS` | 跨通道归并 | Blue |
| `SKIPPED_DUPLICATE` | 重复捕获 | Neutral |
| `REFUND_NOTICE` | 退款提醒 | Blue |

### 状态

| state | 文案 | 色调 |
| --- | --- | --- |
| `BOOKED` | 已入账 | Good |
| `PENDING` | 待确认 | Warn |
| `DISCARDED` | 已丢弃 | Neutral |
| `NOTICE` | 仅提醒 | Neutral |

`extraState`：当处置没体现“已丢弃 / 仍在待确认 / 仅提醒”时，额外补一个状态胶囊。

### 展开后的说明

- `linkedId != null` → `对应账单 #id（点下方「查看对应账单」）`
- `pendingCount > 0` → `仍在待确认队列（确认或丢弃后此状态自动更新）`
- `outcome == REFUND_NOTICE` → `仅提醒，不产生账目（关联退款后生成独立收入记录）`
- 否则 → `无对应账单（未入账或已删除）`

### 清空

`EcoConfirm(danger=true)` → `vm.clearTraces()`；只清证据，不动账单/待确认。

## 7. 文案

- 顶栏：`TRACE` / `记账溯源`；`清空`。
- 页首：`记录中：每次入账相关捕获都留原始来源（最近 1000 条，可在开发者功能里关闭）。` / `未开启：仅显示历史记录。到 开发者功能 →「记录记账来源」开启后才有新记录。`
- 计数：`共 N 条（最新在前）`、`点条目展开原文`。
- 空态：`暂无溯源记录` / `捕获到动账并走完入账流程后会出现`；未开启：`暂无记录` / `开启「记录记账来源」后再走一笔支付`。
- 展开：`商户 X`、`备注 X`、`去重键 X`、`原始来源（通知原文/页面快照/短信原文）`、`支出/收入 X`、`复制原文`、`查看对应账单`。
- 页尾：`溯源只在本机留存，关闭开关后零写入。开启期间最多保留 1000 条。「已丢弃」= 该笔没有入账，或对应账单已被删除。`
- 清空确认：`清空溯源记录` / `只清除溯源证据，不影响任何账单与待确认条目。` / `清空`。
- Toast：`已复制溯源原文`。

## 9. 坑与验收

**坑**

1. `extraState` 不能删：处置结果（如“自动入账”）可能已经过时，当前状态（“已丢弃”）必须额外显示。
2. 「查看对应账单」只在 `linkedId != null` 时出现；不要给所有行都加。
3. `REFUND_NOTICE` 是“仅提醒”，不产生账目；文案已说明，不要改成“已入账”。
4. 溯源最多 1000 条，由数据层裁剪；页面不要自行截断。
5. 清空只清溯源证据，不动账单与待确认；确认文案必须保留这句。
6. 空态区分 `enabled`：开启但无记录 vs 未开启，文案不同。
7. 行卡片连续圆角（`tracePaneShape`），不要每行独立 `EcoPane`。
8. `navigationBarsPadding()` 在最外层 Column；底部 28dp 是额外的。
9. 时间列固定 78dp，规则名过长要省略，不要把时间挤掉。

**验收**

- [ ] 开启/未开启两种页首与空态正确。
- [ ] 处置 + 状态胶囊组合正确（含 `extraState`）。
- [ ] 展开快照、复制、查看账单都可用。
- [ ] 已删除/未入账的行不显示“查看对应账单”。
- [ ] 清空有二次确认，且不影响账单/待确认。
- [ ] 1.25 字体下时间列、规则名、胶囊不挤爆。
- [ ] 长列表滚动到底不被导航栏遮挡。
