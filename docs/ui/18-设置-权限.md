# 18 · 设置 · 权限

权限总览 + 四组必开通道（通知监听、无障碍/页面采集、悬浮窗、银行动账短信）+ 一组可选的「随选朗读（备用手段）」。

源码：`app/src/main/java/com/controleco/app/ui/settings/SettingsPermissionScreen.kt`（约 545 行）
共享：`SettingsPage`、`SettingsSection`、`SettingsPane`、`SettingsStatusRow`、`SettingsSwitchRow`、`SettingsTutorial`、`EcoPill`、`EcoPane`

---

## 1. 路由与入口

- 路由：`settings/permissions`。
- 进入：设置首页 →「权限」。
- 离开：
  - 「去开启 / 去授权」→ 系统设置（通知使用权 / 无障碍 / 悬浮窗），**离开 App**
  - 「横幅 / 权限」→ 本 App 通知渠道设置，或申请 `POST_NOTIFICATIONS`
  - 短信「去授权」→ 系统权限弹窗
- `ON_RESUME` 重新探测所有授权状态（从系统设置返回后刷新）。

## 5. 状态与数据流

### 刷新

`resumeTick` 在 `ON_RESUME` +1；所有 `remember(resumeTick) { vm.isXxx() }` 重新求值。

### 总览（3 项核心）

`listener`、`a11y`、`overlay`（随选朗读**不计入**核心通道，见下）：

- 0 项缺失 → `核心通道已就绪`
- 1–2 项缺失 → `还需开启 N 项核心权限`
- ≥3 项缺失 → `自动记账尚未就绪`
- 胶囊：`通知监听 已连接/未开启`、`无障碍 已连接/未开启`、`悬浮窗 已授权/未授权`。

> **口径差异**：设置首页的权限胶囊按“通知/无障碍/悬浮窗/短信”判断“已就绪”；本页总览按“通知/无障碍/悬浮窗”
> 判断“核心通道”，两边都不含短信/随选朗读。改文案/判定前先决定是否统一；不要只改一处。

### 通知监听

只读：`captureEnabled`、`bankPushEnabled`、`amountReplyEnabled`、`refundLinkEnabled`、`reeauthNeeded`、`canPostNotifications()`。

- 状态行：已授权 `已连接`，否则 `未开启` + `去开启`。
- `reeauthNeeded` → 琥珀提示带 + `去检查`。
- 开关：`setCaptureEnabled`、`setBankPushEnabled`、`setAmountReplyEnabled`、`setCaptureNotifyEnabled`、`setRefundLinkEnabled`。
- 入账提醒行内：
  - 已授予通知权限 → `横幅` → 打开 `CHANNEL_CAPTURE` 通知渠道设置。
  - 未授予 → `权限` → Android 13+ 申请 `POST_NOTIFICATIONS`；结果 Toast。

### 无障碍

- `isA11yEnabled`、`a11yCaptureEnabled`。
- 状态行 + `自动记录支付页面` 开关 + 教程。

### 随选朗读（备用手段，可选）

- `isScreenReaderEnabled`（只读检测，先看包名，避免把本应用入口类名当成读屏）。
- 页面采集的注册组件改用与系统读屏一致的组件身份后，只授权本应用就能读到微信节点
  （2026-10-22 真机实测，见 `docs/无障碍页面捕获兼容性.md`），因此它**不是**必开项。
- 只有状态行 + 教程 4 条，没有开关；文案口径是“页面读不到时再开”。

### 悬浮窗

- `isOverlayGranted`、`overlayConfirmEnabled`。
- `OverlayDecisionHint`：`overlayDecision` 非空才显示；`已弹出` → jade，否则 amber + 原因。
- 未授权时悬浮卡自动回落横幅通知（文案说明）。

### 短信

- `isSmsPermissionGranted`、`smsCaptureEnabled`。
- 开关打开且未授权 → 立即申请 `RECEIVE_SMS`。
- 结果 Toast。

## 7. 文案

- 顶栏：`PERMISSIONS` / `权限`。
- 总览：`核心通道已就绪` / `还需开启 N 项核心权限` / `自动记账尚未就绪`；胶囊见上。
- 通知监听：`通知监听`、`系统授权已确认`、`需要在系统设置中开启`、`已连接`/`未开启`、`去开启`；`应用刚更新过：通知监听可能已被系统静默关闭，若收不到动账请重新开关一次授权。` + `去检查`；开关 `自动记录收款 / 动账通知`、`银行 App 动账推送`、`金额待补录`、`入账提醒`、`退款到账提醒`；行内 `横幅`/`权限`。
- 通知监听教程：侧载解锁、搜索通知使用权、回来显示已连接、长时间无记录重启。
- 无障碍：`无障碍（页面采集）`、`无障碍页面采集`、`自动记录支付页面`；教程含品牌路径 `a11yPathFor(Brand.current())`。
- 随选朗读：`微信页面读取（备用手段）`、`随选朗读（可选）`、`已开启`；教程 4 条（一般不需要 / 空树时再开 / TalkBack 可替代 / 可关闭页面采集）。
- 悬浮窗：`悬浮窗入账`、`悬浮窗权限`、`已授权`/`未授权`、`去授权`；`最近一次捕获：悬浮卡已正常弹出` / `最近一次捕获未弹卡：{原因}（排查用）`；教程 6 条。
- 短信：`银行动账短信`、`收短信权限`、`已授权`/`未授权`、`去授权`、`记录银行动账短信`；教程 4 条。

## 9. 坑与验收

**坑**

1. **“N 项”口径**：设置首页含短信，本页总览只看通知/无障碍/悬浮窗。改动前先决定是否统一；不要只改一处。
2. `resumeTick` 是刷新关键；新增授权状态也必须 `remember(resumeTick)`，否则从系统设置回来不更新。
3. 通知监听/无障碍/悬浮窗的“去开启”是离开 App 的系统页；不要改成应用内弹窗。
4. `reeauthNeeded` 只在应用更新后出现；提示带不能常驻。
5. “入账提醒”行内动作按 `canPostNotifications()` 在 `横幅`/`权限` 之间切换；不要恒定显示“权限”。
6. 短信开关打开时会**自动申请权限**；关掉开关不会撤销系统权限。
7. 悬浮窗未授权不是错误：会自动回落横幅通知，文案不能写成“必须授权”。
8. 随选朗读没有应用内开关，只有系统授权状态 + 教程；它已不是必开项，文案不能写成“必须开启”。
9. 教程里的品牌路径是动态的（`Brand.current()`），不要写死“小米”。
10. 所有教程步骤要保留（侧载解锁、10 秒倒计时、后台弹出界面等），这是用户排障的唯一指引。
