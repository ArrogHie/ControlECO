# 15 · 设置首页

个人页设置卡进入的一级设置页。结构：深色运行状态卡 → `01 自动记账` → `02 系统` → `03 关于` → 本地优先页脚。

源码：`app/src/main/java/com/controleco/app/ui/settings/SettingsScreen.kt`（约 313 行）
共享：`ui/common/SettingsKit.kt`（`SettingsPage`、`SettingsSection`、`SettingsPane`、`SettingsRow`、`SettingsSwitchRow`、`SettingsValueRow`）

---

## 1. 路由与入口

- 路由：`settings`。
- 进入：个人页「设置」卡。
- 离开：
  - 监听 App → `settings/watchedApps`
  - 商户归类 → `settings/merchantRules`
  - 权限 → `settings/permissions`
  - 开发者功能 → `settings/developer`
  - 关于 → `settings/about`
  - 账户/分类/导入不在此页（在个人页或设置子页）
- `ON_RESUME` 重新读取权限与监听数量（从系统设置返回后刷新）。

## 5. 状态与数据流

### 开关

- `captureNotifyEnabled` → `vm.setCaptureNotifyEnabled`
- `overlayConfirmEnabled` → `vm.setOverlayConfirmEnabled`
- `autoEntryEnabled` → `vm.setAutoEntryEnabled`
- `autoUpdateEnabled` → `vm.setAutoUpdateEnabled`

### 权限与运行态

- `listenerGranted` / `a11yGranted` / `overlayGranted` / `smsGranted`：每次 `resumeTick` 重查。
- `running = captureEnabled && (listenerGranted || a11yGranted)`。
  - `captureEnabled` 是总开关（“记录所有应用/捕获所有页面”一类），不是本页开关。
- `grantedCount = 4 项中已授权数量`；`permissionsReady = grantedCount == 4`。
- `watchedCount = CaptureAppCatalog.watched(context).size`；`appTotal = apps.size`。

### 数据

- `lastCaptureAt`：0 → `还没有捕获记录`，否则 `最近捕获 {时间}`。
- `rules.size`：商户归类条数。

### 检查更新

`vm.checkUpdateNow { message -> ... }`：

- `message == null` → `发现新版本，正在打开更新…`（Blue）
- `message.startsWith("检查失败")` → Warn
- 其它 → Good
- 先显示 `正在检查更新…`（Blue）。

## 9. 坑与验收

**坑**

1. `running` 不是“三个开关任一开”，而是 `captureEnabled && (通知监听 || 无障碍)`；不要把 `autoEntry` 算进去。
2. `permissionsReady` 要求 4 项全授权（通知/无障碍/悬浮窗/短信）；只有 3 项时仍显示“待设置”。
3. 权限与监听数量必须在 `ON_RESUME` 重查；否则从系统设置返回不会更新。
4. 三个开关互相独立，不要做联动禁用（除非产品明确要求）。
5. 检查更新的 Toast 色调按 message 前缀判断；改文案时同步。
6. “账本”入口（账户/分类/导入）不在本页，别重复加。
7. 状态卡是固定深色 hero，前景用 `HERO_*` 常量；不要换成 `eco.ink/paper`。
8. 页脚是 `NO CLOUD · LOCAL ONLY`，位置在滚动内容末尾，不是固定底栏。

**验收**

- [ ] 状态卡运行/暂停、最近捕获时间正确。
- [ ] 三个开关写回并持久化。
- [ ] 权限胶囊与 4 项真实授权一致，返回后刷新。
- [ ] 监听 App / 商户归类数量正确。
- [ ] 检查更新各分支 Toast 正确。
- [ ] 所有入口都能到达对应页。
- [ ] 1.25 字体下状态标题、行尾部、页脚不裁。
